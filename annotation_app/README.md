# ProverbGap Human Annotation App

> **The web app that lets native speakers review and validate proverb multiple-choice questions.**

## What is this app?

This is a web application where **annotators** (native speakers of English, Arabic, or Yoruba) review multiple-choice questions (MCQs) generated by our AI pipeline.

Each annotation task asks you to:
1. Read a proverb in its original language.
2. Choose which of four English options (A, B, C, or D) is the correct meaning.
3. Rate how plausible each wrong option (distractor) is on a 1–5 scale.
4. Flag any "shortcuts" that make the question too easy (e.g., one option is much longer than the others).

The goal is to find out which AI-generated distractors are genuinely confusing and which are obviously wrong. This helps us build better benchmarks for AI evaluation.

**Who should use this app?**
- **Native speakers** of English, Arabic, or Yoruba who want to contribute to research.
- **Researchers** running human-validation studies on proverb understanding.
- **Developers** deploying the annotation frontend for data collection.

### Annotator guide

Before starting, annotators should read [ANNOTATOR_ONBOARDING.md](ANNOTATOR_ONBOARDING.md) for a short step-by-step guide and tips for high-quality annotations.

## Step-by-Step Setup

### 1. Clone the repository

```bash
git clone https://github.com/<org>/ProverbGap-MCQ.git
cd ProverbGap-MCQ
```

### 2. Install dependencies

```bash
cd annotation_app
npm install
```

This installs Next.js, Supabase client, Lucide icons, and Playwright (for tests).

### 3. Create a Supabase project

1. Go to [supabase.com/dashboard](https://supabase.com/dashboard) and create a new project.
2. Wait for provisioning to finish (about 2 minutes).
3. Go to **Project Settings → API** and copy:
   - **Project URL** → `NEXT_PUBLIC_SUPABASE_URL`
   - **anon public** key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **service_role** key → `SUPABASE_SERVICE_ROLE_KEY` (⚠️ keep this secret!)

### 4. Configure environment variables

```bash
cp .env.example .env.local
```

Edit `.env.local` with your values:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key-here
ADMIN_PASSWORD=change-me-in-production
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

> **Security note:** `.env.local` is in `.gitignore`. Never commit it.

### 5. Set up the database

In the Supabase dashboard, go to **SQL Editor** and run the SQL files in this order:

1. Copy the contents of `supabase/schema.sql` and run it.
2. Copy the contents of `supabase/rpc.sql` and run it.

Alternatively, use the setup script:

```bash
npm run setup-db
```

> The setup script prints instructions because it needs the SQL to be run manually in Supabase first. After running the SQL files, use `npm run upload-items` to load data.

### 6. Upload annotation items

The app needs data to display. If you have a CSV file (e.g., `human_validation_sample_60.csv` from the generation pipeline), upload it:

```bash
npm run upload-items
```

**Expected CSV columns:**

| Column | Example | Description |
|--------|---------|-------------|
| `validation_id` | `ENG-001` | Unique ID for the item |
| `language` | `English` | Source language |
| `proverb` | `A bird in the hand is worth two in the bush` | The original proverb |
| `option_a` | `A bird in the hand is worth two in the bush` | Option A |
| `option_b` | `Don't count your chickens before they hatch` | Option B |
| `option_c` | `Every cloud has a silver lining` | Option C |
| `option_d` | `You can't have your cake and eat it too` | Option D |
| `correct_label` | `A` | The correct answer letter |
| `gold_meaning` | `Value what you have over risky gains` | Curated English meaning |
| `is_attention_check` | `false` | `true` for trap items |

> **Where do I get this CSV?** It is produced by the generation pipeline in `data/production/`. See [GETTING_STARTED.md](../GETTING_STARTED.md) for how to generate it.

### 7. Run the development server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser. You should see the annotation interface.

## How to Deploy to Vercel

The fastest way to share the annotation app with annotators is to deploy it to Vercel.

### One-command deploy (CLI)

```bash
# From the annotation_app directory
vercel
```

Follow the prompts. Vercel will detect Next.js and deploy automatically.

### Or deploy via the Vercel dashboard

1. Push your code to GitHub.
2. Go to [vercel.com/new](https://vercel.com/new) and import your repository.
3. Set the **Root Directory** to `annotation_app/`.
4. Add the following **Environment Variables**:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `ADMIN_PASSWORD`
   - `NEXT_PUBLIC_APP_URL` (set this to your Vercel URL, e.g. `https://proverbgap-annotator.vercel.app`)
5. Click **Deploy**.

### After deployment

1. Visit your Vercel URL.
2. Run `npm run upload-items` locally to populate your production database.
3. Share the URL with annotators.

## How to Export Annotations

When annotation is complete, export all data for analysis:

```bash
npm run export-annotations
```

This downloads a CSV file (`annotations_export.csv`) with all annotations, including:
- Item IDs and proverb text
- Selected answers and correctness
- Confidence ratings
- Time taken (milliseconds)
- Plausibility ratings per option (JSONB)
- Shortcut flags
- Attention check results

The export script uses `SUPABASE_SERVICE_ROLE_KEY` to read all rows. No authentication is required from the browser.

## Database Schema

### `pg_annotation_items`

Stores the 60 MCQs for human annotation.

| Column | Type | Description |
|--------|------|-------------|
| `id` | TEXT (PK) | Internal item ID |
| `validation_id` | TEXT | Hash linking to master data |
| `language` | TEXT | `English`, `Arabic`, or `Yoruba` |
| `proverb` | TEXT | Original proverb text |
| `option_a/b/c/d` | TEXT | The 4 multiple-choice options |
| `correct_label` | TEXT | Gold answer (hidden from browser) |
| `gold_meaning` | TEXT | Curated meaning (hidden from browser) |
| `is_attention_check` | BOOLEAN | Flag for attention-check items |
| `item_metadata` | JSONB | Additional metadata |
| `lock_expires_at` | TIMESTAMPTZ | Concurrency lock timestamp |

### `pg_annotator_profiles`

Stores anonymous annotator demographics.

| Column | Type | Description |
|--------|------|-------------|
| `annotator_id` | TEXT (PK) | Anonymous ID from localStorage |
| `nickname` | TEXT | Optional display name |
| `language_expertise` | TEXT | Primary language |
| `is_native_speaker` | TEXT | `yes` / `no` / `near-native` |
| `age_group` | TEXT | Optional |
| `education_level` | TEXT | Optional |
| `country` | TEXT | Optional |
| `device_info` | TEXT | Browser user agent |
| `created_at` | TIMESTAMPTZ | Account creation time |

### `pg_annotations`

Stores one row per item per annotator.

| Column | Type | Description |
|--------|------|-------------|
| `id` | UUID (PK) | Unique annotation ID |
| `item_id` | TEXT (FK) | Links to `pg_annotation_items` |
| `annotator_id` | TEXT | Links to `pg_annotator_profiles` |
| `selected_answer` | TEXT | `A`, `B`, `C`, or `D` |
| `correctness` | TEXT | `correct` / `incorrect` (computed server-side) |
| `confidence` | TEXT | `high`, `medium`, or `low` |
| `time_taken_ms` | INTEGER | Milliseconds spent on item |
| `is_attention_check` | BOOLEAN | Whether this was an attention check |
| `attention_passed` | BOOLEAN | Whether attention check was passed |
| `annotator_notes` | TEXT | Optional text notes |
| `plausibility_ratings` | JSONB | Map of option letter to 1–5 plausibility score |
| `shortcut_flags` | TEXT[] | Array of detected shortcut artifacts |
| `created_at` | TIMESTAMPTZ | Submission time |

> **Unique constraint:** `(item_id, annotator_id)` — one annotation per item per annotator.

## Key Design Decisions

1. **No authentication:** Annotators get a random ID stored in `localStorage`. Zero friction, but no cross-device tracking.
2. **Supabase RPC for concurrency:** `pg_get_items` uses `FOR UPDATE SKIP LOCKED` to prevent two annotators from getting the same item. 30-minute lock auto-releases abandoned batches.
3. **Hidden gold answers:** The `correct_label` and `gold_meaning` columns are never returned to the browser. The RPC only returns the public columns needed for annotation.
4. **Batch-based flow:** Items are fetched in batches of 10. After completing a batch, annotators can continue with the next batch.
5. **Attention checks:** Every 10th item is an attention check with a clear instruction. Results are tracked separately.
6. **Client-side only DB writes:** No API routes, no server actions. RLS policies are the only security boundary.

## Troubleshooting

### Supabase connection errors

**Symptom:** "Failed to fetch" or "NetworkError" when loading the app.

**Solutions:**
- Verify `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` in `.env.local`.
- Make sure `pg_get_items` RPC exists in your Supabase database (run `supabase/rpc.sql`).
- Check that RLS policies allow anon users to execute the RPCs.

### "No items available" on the annotate page

**Symptom:** The app says "No more items" immediately.

**Solutions:**
- Run `npm run upload-items` to populate the database.
- Check that `human_validation_sample_60.csv` exists in the parent directory.
- Verify items in `pg_annotation_items` have `is_attention_check = false` and `lock_expires_at IS NULL`.

### Vercel build fails with "Module not found"

**Symptom:** Vercel deployment fails during `npm run build`.

**Solutions:**
- Ensure Node.js 22 is selected in Vercel project settings.
- Delete `node_modules` and `package-lock.json`, then run `npm install` locally and commit the updated lock file.
- Check that `next.config.ts` does not reference local files outside the deployment root.

### Playwright tests fail

**Symptom:** Tests timeout or fail with browser errors.

**Solutions:**
- Install browser binaries: `npx playwright install chromium`
- Make sure the dev server is running on port 3000 before running tests.
- For CI, use `npx playwright install --with-deps chromium`.

### Admin page returns 404

**Symptom:** `/admin` shows "This page could not be found."

**Solutions:**
- Make sure you're on the latest version of the app.
- Verify the admin route exists in `src/app/admin/` (if applicable to your branch).
- Check that `ADMIN_PASSWORD` is set in environment variables.
